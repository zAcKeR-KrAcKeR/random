# Project: Offline AI Contract-to-Invoice Verification Engine

## Core Rules & Hardware Constraints
- **100% Offline Execution**: Zero external cloud API calls. Use local `ollama` (`http://localhost:11434`) for LLM inference and local CPU libraries (`pymupdf`, `pdfplumber`, `rapidocr-onnxruntime`) for document parsing.
- **Hardware Profile**: NVIDIA RTX 4050 (6GB VRAM) + Intel Core i7. Keep all PDF/OCR parsing strictly on CPU so all 6GB VRAM is reserved for `qwen2.5:7b-instruct` (or `llama3.1:8b`).
- **Neuro-Symbolic Separation**: NEVER use the LLM for math, tax calculations, or pass/fail decisions. The LLM only extracts unstructured PDF text/tables into strict Pydantic JSON schemas. Pure Python (`engine/validator.py`) performs all deterministic validation and arithmetic.
- **Persistence**: Local `sqlite3` database (`forensic_contracts.db`).
- **UI**: Streamlit (`app.py`) with 2 main operational tabs + 1 ledger/exhaustion view.

Phase 4 Prompt: The 5-Gate Deterministic Verification Engine
Once Phase 3 is done, paste this fourth prompt:
@workspace Now let's build **Phase 4: The Deterministic Rule & Math Verification Engine (`engine/validator.py`)**.

Create `engine/validator.py` using pure Python arithmetic (zero LLM calls). Define a `ValidationResult` Pydantic model containing:
- `verdict`: Literal["MATCHES (APPROVE)", "MISMATCH (REJECT)"]
- `red_flags`: list[dict] (each with `severity`: "CRITICAL" | "WARNING", `gate`: str, `line_ref`: str, `description`: str, `contract_clause`: str, `financial_impact`: float)
- `line_reconciliation`: list[dict] (side-by-side per line: Description, Qty Claimed, Rate Claimed, Rate Allowed, Base Claimed, Base Verified, Variance, Status)
- `summary_comparison`: dict comparing Claimed vs. Verified for: `subtotal_base`, `total_tax`, `gross_total`, `advance_deduction`, `retention_deduction`, `net_amount_payable`, and `total_overcharge_prevented`.

Implement `verify_invoice_against_contract(invoice: InvoiceSchema, contract: ContractSchema, ledger_summary: dict) -> ValidationResult` with these exact **5 Verification Gates**:

1. **Gate 1: Milestone Rate & Amendment Verification (Catches Test Case 1 - Unexplained Rate Jump)**:
   - Match each `MILESTONE` invoice line item to the active contract milestone (using highest `amendment_no` for that milestone code, or matching by name/stage).
   - Compare `unit_rate_billed` vs `contract_milestone.unit_rate`.
   - If `unit_rate_billed > contract_milestone.unit_rate` (e.g., billed ₹84,625 vs contracted ₹44,625), raise a `CRITICAL` Red Flag detailing the exact per-unit rate jump (+₹40,000/unit) and total line overcharge, and compute `verified_base = quantity_billed * contract_milestone.unit_rate`.
   - Also verify line arithmetic: `quantity_billed * unit_rate_billed == base_amount_billed`.

2. **Gate 2: Reimbursable Caps & Stage-Split Enforcement**:
   - For `REIMBURSABLE_FARMER` or `REIMBURSABLE_CROP` lines, check against `contract.reimbursable_caps`.
   - Enforce per-unit ceiling (e.g., if Tree/Crop compensation is billed at ₹35,000/tower against a ₹20,000 cap, flag `CRITICAL` and cap verified rate at ₹20,000).
   - Enforce stage-gate split (e.g., if Farmer Compensation max is ₹40,000 with 50% allowed at Foundation, max allowed rate at Foundation is ₹20,000/tower).

3. **Gate 3: GST Inclusivity vs. Exclusivity Check (Catches Test Case 2 - GST Double-Dipping)**:
   - Check `contract.gst_treatment`.
   - If `contract.gst_treatment == "INCLUSIVE"` and the invoice adds CGST/SGST/IGST (`invoice.total_tax_amount > 0`), raise a `CRITICAL` Red Flag: *"Contract rates are INCLUSIVE of GST, but vendor charged extra GST on top of contracted rates."* Set `verified_tax = 0.0` (so the 18% overcharge is completely stripped from Verified Payable).
   - If `contract.gst_treatment == "EXCLUSIVE"`, recalculate expected tax (`verified_subtotal_base * (contract.standard_gst_rate_pct / 100.0)`) and flag any tax rate discrepancy.

4. **Gate 4: Advance Recovery & Retention Deduction Math Check**:
   - Determine remaining unrecovered advance from `ledger_summary["advance_recovered_to_date"]`.
   - Calculate required advance deduction on this invoice based on `contract.advance_recovery_rule`:
     - If `EQUAL_INSTALLMENTS` (e.g., ₹15,00,000 across first 2 invoices = ₹7,50,000 per invoice), check if `invoice.advance_adjusted` matches the required installment (up to remaining unrecovered advance).
     - If `PERCENTAGE_PER_INVOICE`, compute `verified_subtotal_base * (contract.advance_recovery_pct / 100.0)`.
   - Flag a `CRITICAL` mismatch if the vendor under-deducted the required advance recovery.
   - Calculate expected retention: `verified_retention = verified_gross * (contract.retention_pct / 100.0)` (or on base as per standard practice—check if vendor calculated 5% on gross or base and verify math).

5. **Gate 5: Cumulative Contract Scope & Exhaustion Check**:
   - Check if `cumulative_units_billed + current_units_billed` for any milestone exceeds `contract.total_scope_units * (1 + contract.scope_tolerance_pct / 100.0)` (e.g., 275 towers + 10% = 302.5 towers max).
   - Check if cumulative verified spend exceeds `contract.total_contract_value`.

Compute final `verified_net_payable = verified_gross - verified_advance_deduction - verified_retention_deduction`. Set `verdict = "MISMATCH (REJECT)"` if any `CRITICAL` red flag exists or if `abs(invoice.net_payable_claimed - verified_net_payable) > 1.0`.
